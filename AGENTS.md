### Shared hard rules — from `STANDARD.md` sections 1–6

> These bind on every edit in this repository. They are carried here rather than pointed at,
> because a session may not be able to read `~/.agents`. The canonical text is
> `~/.agents/standards/STANDARD.md`; this is a generated copy — change it there, never here.

#### 1. Root files (the finalized layer)

Every repository carries these at its root:

```
AGENTS.md  README.md  README.zh-CN.md  CHANGELOG.md  MAINTENANCE.md  MAINTENANCE.zh-CN.md
LICENSE  .gitignore  .github/workflows/ci.yml
```

plus the `docs/` tree (process drafts live in `docs/reports/`, section 2) and exactly one manifest:

- **plugin** → `package.json`
- **tool** → `pyproject.toml`

A missing file is reported as a defect.

> **This list is dimension A's shape; the other two narrow it.** B replaces the single `ci.yml`
> with its own multiple workflows and carries no `LICENSE`; C keeps only `AGENTS.md`,
> `README.md`, `CHANGELOG.md`, `.gitignore`, `scripts/check_agents.py` and a
> single `ci.yml`, and **must not carry** `README.zh-CN.md`, `MAINTENANCE*` or `LICENSE`.
> A/B bilingual pairs are aligned on both sides; there is **no repository-level mirror exception**.
> About follows section 10. See `dimensions/b.md` and `dimensions/c.md`.

> **`AGENTS.md` shape.** It opens with the `Dimension.` pointer block, then the generated
> `standards-core` block (sections 1–6 of this file plus the repository's own `dimensions/<x>.md`,
> rendered by `scripts/render_standards.py`), then the dimension's named sections in a fixed
> relative order — A: `Hard rules`, `Docs & commits`, `Recording conventions`; B/C: `硬边界`,
> `文档与提交` — interleaved freely with the repository's own sections. A bilingual pair names them
> per side, each in its own language. The pointer and the generated block are carried by every
> repository; the named sections are fixed only where they already exist. Exact names, block
> markers and the skeleton: `procedures/agents-md.md`.

> **The `README` opening (every repository).** After the title and badges, four labelled items in
> this order — **What it is**, **What it solves**, **How to run** (a knowledge repository with no
> runnable product: **How to use**), **Where to look** — then exactly one H2 contents block
> (`## 📖 Table of Contents` / `## 📖 目录`), which is the **first** `##` in the file and is
> **generated from that file's own `##` headings, never hand-kept**. A bilingual pair carries both on
> each side in its own language; C's single Chinese `README.md` carries the Chinese labels
> (**是什么** · **解决什么** · **怎么跑** / **怎么用** · **去哪看**). A contents list that names a
> heading the file lacks, or omits one it has, is a defect. The labels, the GitHub anchor algorithm
> and the worked examples: `procedures/readme.md`.


#### 2. Process-draft location

Phase / process drafts — `STATE.md`, `PLAN.md`, `VERIFY.md`, `AUDIT.md`, `PROFILE.md`,
`REVIEW-PACK.md` — live in **`docs/reports/`** and are **git-ignored**.

- The ignore rule is a **non-anchored** `reports/` (no leading slash), so it also covers
  `docs/reports/`.
- A process draft at the repository root, or a root-level `reports/` (not under `docs/`),
  is a misplacement.
- Process drafts must **never be committed**.


#### 3. CHANGELOG format

- Entries are `D-###`, monotonic, never reused. A gap is a failure, not cleanup.
- `kind` ∈ `fix | perf | taste | guard | revert | chore`.
- **tools**: commits whose subject starts with `feat` are excluded **by class**.
- **plugins**: the protected sections (`Changes vs upstream`, `Credits & Attribution`) are not touched.
- An entry asserts what was true **as of its commit**; never re-verify an old entry and never
  hand-copy an aggregate count.
- `kind` is cut by **who may demand a revert**: `fix` = a bug; `perf` = measurable degradation only,
  not correctness; `taste` = only the owner's preference — zero obligation, discardable wholesale
  on an upgrade; `guard` = no behaviour change, detects drift; `revert` = withdraws earlier work;
  `chore` = cleanup owed nothing either way.
- **An empty covered window is a failure**, not "nothing worth recording": a check over an empty set
  proves nothing.
- **`Symptom` names the mechanism, never the session**: no prompt text, no command lines, no real
  config paths.


#### 4. Runtime ignore list

Every `.gitignore` includes at least:

```
.venv/  venv/  __pycache__/  *.db  *.db-wal  *.db-shm  .pytest_cache/  reports/
```

Runtime state (databases, caches, virtualenvs) and process drafts must never be committed.


#### 5. Conflict rule

A repository's own `AGENTS.md` may add rules that are **stricter or more specific** than this
standard — that is correct and must not be "unified" away. But a repository must **not** keep a
rule that *contradicts* this standard: the standard is the floor, and where a repository has
drifted below it (misplaced process drafts, non-English non-whitelisted docs outside its
dimension's exemptions, unpinned CI), the repository is aligned to this standard.


#### 6. Remotes and pushing

- **Push over SSH, never HTTPS.** Before pushing, verify the push URL:
  `git remote get-url --push origin` must start with `git@`. If it starts with `https://`,
  fix it first: `git remote set-url --push origin git@github.com:<owner>/<repo>.git`.
- Do not record a specific clone's remote URL/transport in committed docs — state this **check**
  instead (a recorded URL is false for every other clone and rots when the remote changes).


### Dimension A additions — beyond the shared rules above

**A — open source (strict).** Everything in `STANDARD.md` — the root file layer, the

#### 1. Language policy

**The front door is strict and has no repository-level exceptions.**

- **Bilingual pairs** (both sides required, `##` sections aligned; missing or misaligned is a defect):
  - `README.md` ↔ `README.zh-CN.md`
  - `MAINTENANCE.md` ↔ `MAINTENANCE.zh-CN.md`
  - `INVARIANTS.md` ↔ `INVARIANTS.zh-CN.md` — **only when the repo already has the pair**.
- **About is English** (`STANDARD.md` section 10).
- **Everything outside the whitelist is English** — documents, code, comments, CLI/TUI text.
  A non-whitelisted `.md` that contains Chinese is a defect, except for the product-content rule
  below.
- **Commit messages are English** — the whole message, subject *and* body. Each repository's
  `AGENTS.md` still lists its own Conventional-Commits prefix set; only the language is fixed
  here: an English prefix with an English subject, never Chinese.
- **Not judged**: third-party / machine-generated content — `po/`, `locale/`, `screenshots/`,
  upstream `src/`, `thirdparty/`.
- **CHANGELOG.md is not whitelisted → it is English.** Same for `docs/**/*.md` and every
  `AGENTS.md`, except for the product-content rule below.
- **Allowed: quoted literals.** Non-English text is **not** a defect when it is a *verbatim
  literal* rather than prose — a Markdown anchor into a whitelisted `.zh-CN.md` heading, a
  fixture or marker string defined in code (together with the code that defines it), or a
  quotation of such a literal inside an otherwise-English file. The surrounding prose is still
  English. This is what lets `copyous` link to a Chinese README heading and quote its CJK
  fixture, and `burn-my-windows` name the `原 MAINTENANCE section N` marker its own test defines.
- **Product content may be bilingual when the product itself is.** A repository whose product is
  bilingual by design may keep Chinese product content — CLI output text, product templates, seed
  data, fixtures, and the Chinese documentation that describes that product — and records this in
  its own `AGENTS.md`. This is a product-content rule, not a front-door exception: it does **not**
  relax the README pair, the MAINTENANCE pair, the INVARIANTS pair or About. `agent-os` is the
  current case: its CLI output, templates, seed data and CJK fixtures are Chinese because its
  retrieval is measured to need Chinese tags; its README pair is fully aligned and its About is
  English.

#### 2. CI

- CI runs the **offline layer only**.
- Checkout uses **`fetch-depth: 0`** (`check:log` walks `git log <anchor>..HEAD`).
- **The pinned version is the repository's own declared floor** (lowest supported version):
  - source order: the `README` Requirements table → `pyproject.toml` `requires-python` /
    `package.json` `engines`.
  - **No declared floor → declare one first, then pin** — never invent a version.
  - **A declared support range must be covered at both ends** (a CI matrix). Testing only a
    middle version is incomplete coverage.
- Entry commands:
  - **plugin**: `npm test` + `npm run check:log`
  - **tool**: one command that runs the whole suite (see section 3)
- **A plugin CI also runs `npm run test:coverage`** after the entry commands — a coverage
  *reading* (Node's built-in), **not a gate**: it has no threshold, so it cannot fail the run.
  It reports only what Node can import — the pure modules plus the test files themselves; the
  shell-bound extension body (and, where nothing is importable, the whole product) is absent by
  design.

#### 3. Test entry commands

- **plugin**: `npm test` (tests live in the **singular** `test/`).
- **tool**: `pytest scripts/tests -q` or `unittest discover -s scripts/tests`
  (tests live in `scripts/tests/`, files named `test_*.py`).

## What this is

A **read-only** six-tab board over the local usage trackers: `cbut` (CodeBuddy),
`ocut` (OpenCode) and `qcut` (Qoder CN). Layers, in dependency order:

1. `scripts/aut_sources.py` — one adapter per tracker: where its `usage.db` lives,
   the SQL expressions that normalise its token and project columns, and how to
   launch it. The only file that knows a schema.
2. `scripts/aut_model.py` — the cross-tool aggregation every tab draws. Pure:
   `(start_ms, end_ms) -> rows`, no Textual import, so the numbers are testable
   without a terminal.
3. `scripts/aut_chart.py` — text-only bars: `share_bar`, `pct`. Pure numbers
   in, `rich.Text` out, no Textual, so the drawing is testable glyph by glyph.
   A proportion is the easiest place here to lie by accident.
4. `scripts/aut_picker.py` — the custom date-range picker, ported verbatim from
   the tracker family (same 79x30 layout, same chips). Kept in its own file so
   the board stays about the board.
5. `scripts/aut_app.py` — the Textual board: top bar, six panes, detail screens.
6. `scripts/aut_report.py` — `aut json`, `aut skills` and `aut sync`.

`bin/aut` is a bash dispatcher. **It is bash on purpose**: it must still run and
print a useful error when the venv is missing or broken.

This repository is public.

## Hard rules

- **Never parse a tracker's logs.** The three trackers own collection; this repo
  reads their SQLite index. A second parser is a second truth and will drift.
- **Never write.** Every connection is `file:...?mode=ro`. `r` and `enter` shell
  out to the tracker's own command; the board itself stays a reader.
- **Never invent a number.** A source that reported credits but no token shows
  `—`; a schema that moved shows `error` on the Sources tab and contributes
  nothing to the merges. `0` is a claim, and it must be true.
- **Do not show money.** Tokens are the unit. The three trackers report credits,
  credits and dollars; a single cost column would merge three units.
- **Do not merge what is not the same thing.** Tool names merge on case alone
  (`Read` / `read`). `Bash` and `shell` stay apart, and `pending` is never folded
  into `fail` — those are guesses, not facts. Models *do* merge by name across
  trackers (that is the point of the Tokens tab); provider is a column, not a
  split.
- **One number, labelled.** Every token figure the board prints is the tracker's
  own Usage Total (cbut: prompt + completion + cache hit; ocut: full prompt +
  output + the hit re-added; qcut: input + output + cache read). The providers'
  own API totals are not read anywhere. A number that says neither input, output
  nor cache is the Usage Total, and a second unlabelled total beside it is a bug.
- **One bar, one scale.** Every bar in a table shares its scale; a bar scaled to
  its own row would draw a 12M and an 81M source at the same height, which is a
  lie the eye cannot catch. The percentage beside it is its share of the window.
- **One model is one row — in the merged views only.** `canonical_model` in
  `aut_model` is the single place a spelling is folded: case, `.`/`_` → `-`,
  the free-route suffix, and `MODEL_ALIASES` for the ids no rule can infer
  (Qoder's builtin routes carry no machine-readable id — its `provider_id` is
  NULL). The Tokens by-model view and the dashboard read the folded key; Usage,
  the per-call rows and the model × tracker view keep the spelling the tracker
  wrote, and the three trackers are not touched at all. A row carries its
  `spellings` because the detail queries by them: a merged row and its
  drill-down must total the same.
- **A merged row names its sources.** A number that sums several trackers says
  which ones — `cbut+ocut`, `all` — because the total alone cannot be traced
  back to a tool. The tag sits beside the name and is paid for out of the name
  field, never out of the card: a line that wraps loses the alignment the list
  is for.
- **Cards grow, then the pane scrolls.** A list card takes the height its rows
  need — never a fixed row count that silently hides the rest — and the pane
  scrolls once the screen is full.
- **A row is sized from its card, never from a constant.** The budget is the
  card's measured content width (less one column for the scrollbar the pane may
  grow), and every field in the row is measured from the data: a nine-character
  total in a seven-cell field wrapped the percentage onto the next line. What
  gives way, in order: the bar, the origin tag, the percentage — the name
  absorbs the slack. The same rule applies to the KPI line, which drops whole
  facts rather than wrapping one.
- **Keep the three TUIs untouched.** Going deeper is `suspend()` + the tracker's
  own binary, never a re-implementation of its views.
- **Keep the keys aligned with the family.** `r` syncs, `s` sorts, `/` filters,
  `d` opens the range picker, `tab` cycles. A different meaning for a shared key
  is a bug, not a preference.
- **The total comes before its parts.** Where a row shows the usage total and
  the input / output / cache split, the total is the leading column: it is the
  number the row is ranked and sorted by, and the four parts explain it.
- **State above the table, provenance below, keys in the footer.** The caption
  names the sort and the grouping (`sort: usage total ▼ (s)`); the line under the table
  says how many indexes were read, how big they are and when they were synced.
  This is the three trackers' layout, and the reason `s` is discoverable at all.
- **The footer only lists keys that work on the tab.** `AutApp.check_action` is
  the one place a key's applicability lives: it answers for the footer and for
  dispatch at once. Do not re-add a "this tab has no sort order" notification —
  a key that cannot act must not be offered. A binding a focused widget hides
  (Textual's own `enter` on `DataTable`) is re-declared in the `Table` subclass,
  not duplicated at app level: the app-level copy never fires.
- **`suspend()` is for handing over the terminal, not for running a command.**
  `enter` on Sources suspends because the child owns the screen; `r` must not,
  because the child owns nothing the user needs to watch. Background work is
  `asyncio.create_subprocess_exec` with output captured, a hard timeout, and one
  reload at the end — the status line, not a restart, reports progress.

## Commands

```bash
./install.sh                                  # venv + ~/.local/bin/aut symlink
python3 -m unittest discover -s scripts/tests # stdlib unittest; pytest discovers them too
./bin/aut json --days 7                       # the snapshot, as JSON
./bin/aut skills --days 30                    # skill usage without the TUI
./bin/aut cbut                                # jump straight into one tracker
```

## Layout

```
bin/aut                 bash dispatcher: tui | cbut/ocut/qcut | json | skills | sync | --help
scripts/aut_sources.py  the adapters (SOURCES) and the Snapshot shape
scripts/aut_model.py    cross-tool aggregation: tokens, entities, timeline, kpis
scripts/aut_picker.py   the custom date-range picker (ported from the family)
scripts/aut_app.py      the Textual board: six panes + two detail screens
scripts/aut_chart.py    the share bar and its percentage, shared by every pane
scripts/aut_db.py       read-only connections, formatting, sparkline
scripts/aut_report.py   headless json / skills / sync
scripts/tests/          adapters + aggregation against temp databases, board smoke tests
```

## Docs & commits

- **Docs are bilingual**: `README.md` (English, landing page) and `README.zh-CN.md` (Chinese).
  Edit both together and keep section order aligned; a section added on one side alone is drift.
- Commit messages are **English** and follow Conventional Commits (`feat:` / `fix:` / `docs:` /
  `chore:`), code before docs.

## Recording conventions

Commit subjects are English. The CHANGELOG records the non-feature commits — the
repairs, the guards, the withdrawals — and states what was true as of its commit,
not current state.

## Listed on the GitHub profile

**This repository is listed on the owner's profile front page**, and this section is the reciprocal
of `SHADE-glitch/SHADE-glitch`'s §6 index — that file is the authoritative rulebook, and
the profile-listing rule in the standards-core block above holds the shared listing triggers. These facts must stay true
on the front page:

- **Rename / transfer / delete** — the profile link dies; fix the row.
- **Purpose drift** — the profile's one-line description must still be true. The claims it copies —
  *"one read-only board"*, *"no second parser"*, *"no writes"* — are **promises**, not slogans.
- **Source set change** — the About names `cbut`, `ocut` and `qcut`. Dropping or adding a source
  makes that sentence false; change it in the same commit.

board that reads the three indexes and hands the terminal over — not a fourth tracker, and not a
sibling's About copied across.
