## 1. Overview

### Code structure and data flow

- `scripts/aut_sources.py` — the three tracker adapters, the Sources snapshot SQL, the Usage Total
  expressions, the window and idle decisions.
- `scripts/aut_model.py` — cross-source aggregation (token/model/entity/KPI/timeline),
  `canonical_model` folding, drill-down queries.
- `scripts/aut_app.py` — the Textual TUI, table cells, Sources/Dashboard/Tokens/entity detail
  screens, background sync.
- `scripts/aut_report.py` — the headless `json` / `sync` commands.
- `scripts/aut_picker.py` — date/time parsing, window bounds, the date-range picker.
- `scripts/aut_db.py` — read-only opening, formatting, sparkline.

### Verified clean points

These are not "nothing was seen" — each was confirmed against the audit axes:

- **Read-only**: every connection goes through `open_ro()` with `mode=ro`; no code in the
  repository writes a tracker DB. `r` / `enter` only call the tracker's own command.
- **SQL injection**: table and column names all come from the constant `SOURCES` /
  `ENTITY_TABLES`; values are all bound with `?`. `_model_in()` only concatenates placeholders
  (`aut_model.py:384-386`); no user input reaches a SQL identifier.
- **Subprocesses**: `asyncio.create_subprocess_exec` (`aut_app.py:1398-1402`) and
  `subprocess.call` (`aut_report.py:82`) both pass argv lists; there is no `shell=True`.
- **Path traversal**: DB paths are built from the fixed `Path.home() / ".local/share/..."`; there
  is no user-controlled path.
- **Division by zero / empty values**: `pct()`, `share_bar()` guard `total <= 0`
  (`aut_chart.py:22-38`); `_delta()` guards `prev <= 0` (`aut_app.py:172-180`);
  `fmt_tokens(None)` returns `—`, `fmt_age(None)` returns `never` (`aut_db.py:50-84`).
- **Tests**: 52 green, covering the adapters, windows, merges, read-only and basic TUI
  interaction.

### Systemic issues (by impact)

1. **Token-honesty gap**: the Sources layer knows "no token means print `—`", but the merge layer
   coerces `None` to `0` or treats a partial value as a complete one. Directly violates the
   `AGENTS.md` rule "Never invent a number". → **P0-1**, related to **P1-12**.
2. **Window/entity consistency**: Sources ignores a custom end time; `last_seen`/idle only take
   `MAX(ts)` inside the window; the entity drill-down matches a single displayed spelling exactly;
   `active_days` takes the max instead of the union; the entity average counts NULLs in the
   denominator. → **P1-1 ~ P1-6**.
3. **Silent failure**: `_per_source()` catches `sqlite3.Error` and `continue`s; Sources queries
   only a subset of columns, so "Sources shows ok, Tokens silently loses a source". → **P1-9**.
4. **Headless and rendering**: `aut json` indirectly depends on Textual through `aut_picker`;
   tracker strings enter DataTable/Static/notify as raw markup content. → **P1-7, P1-8**.
5. **Documentation/state drift**: README, HELP, `install.sh`, `_synced_ms`, `--days` and friends
   disagree with the implementation. → **P2**.

### Audit limitations

- The concurrency issue (P1-10) is a code-level risk; no concurrency stress reproduction was run.
  All other P0/P1 findings have code evidence or a `/tmp` probe reproduction.
- `install.sh` was not run, the real TUI was not started, and no real tracker DB was read; all
  probes used a temporary `HOME` and self-built SQLite fixtures.

## 2. P0

### P0-1 BYOK / no-token sources are treated as 0 in the merged views — fixed in `68b2a9c`

**Evidence**

`aut_sources.py:128-137` already distinguishes "no token" correctly:

```python
tokens = int(total) if total is not None else 0
...
if tokens == 0 and money:
    tokens_value: int | None = None
else:
    tokens_value = tokens
```

But the merge layer coerces every SQL `NULL`/0 to an integer:

```python
# aut_model.py:190-193
total=int(r[6] or 0), requests=int(r[7] or 0),
```

```python
# aut_model.py:354-356
tokens = int(row[0] or 0)
out.tokens += tokens
out.per_source[key] = tokens
```

The Dashboard then draws the `0` as a real value:

```python
# aut_app.py:780-786
if total <= 0:
    out.append("nothing recorded in this window", style="dim")
    return out
...
value = k.per_source.get(source.key)
...
out.append(f"{source.label} ", ...)
```

**Reproduction** (`/tmp/opencode/audit_probe2.py`)

qcut's BYOK row: `credits=12.5`, `input_tokens`/`output_tokens` are `NULL`, `has_usage=0`.

```text
snapshot qcut tokens= None cost= 12.5
kpis tokens= 0 per_source= {'qcut': 0}
token_rows= [('byok', 0, 1)]
model_totals= [('byok', 0, 1)]
```

- The Sources row shows `—` and the JSON holds `null`; the Tokens row shows `0` and the
  Dashboard's per-source is `0`.
- With other sources present, the Dashboard shows `Qoder CN 0 0%`; with only the BYOK source it
  shows `nothing recorded in this window`.
- On one screen, Sources says "no tokens" while Tokens/Dashboard say "used 0".

**Impact**

- Directly violates `AGENTS.md:40-42`: *"**Never invent a number.** A source that reported
  credits but no token shows `—` ... `0` is a claim, and it must be true."*
- For a BYOK user, the most central question — "did I use anything at all?" — is answered wrong;
  the merged total is understated.
- This is not a display-layer nit: `kpis`, `model_totals` and `by_source` all received the wrong
  `0`, and every later sort, share and trend is built on it.

**Fix direction** (landed in `68b2a9c`: the adapters use their trackers' own `CASE`
expressions and `NULL` propagates through `TokenRow`, `ModelTotal`, `CallRow` and `Kpis`; a
merged row with any unreported call is unknown, and the views print `—`)
- Give `TokenRow.total`, `ModelTotal.total`, `Kpis.tokens` and `Kpis.per_source` the ability to
  express "unknown" (`int | None` or an explicit `tokens_known` flag).
- Sum only known values when merging; unknown values print `—` and take no part in the "0"
  sorts and shares.
- At minimum, keep `None` in `token_rows` first, propagate it through `model_totals` /
  `by_source` / `kpis`, and add a regression test from `snapshot` to Tokens/Dashboard.

### P1-3 Sources ignores a custom fixed end time — fixed in `68b2a9c`

**Evidence**

`Source.snapshot()` / `_read()` have only a lower bound, no `end_ms`:

```python
# aut_sources.py:80-81
def snapshot(self, days: int, now_ms: int | None = None,
             since_ms: int | None = None) -> Snapshot:
```

```python
# aut_sources.py:120-126
since = cutoff_ms(days, now) if since_ms is None else since_ms
total, cost, calls, sessions, last_ts, real_avg = conn.execute(
    f"SELECT ... FROM {self.table} WHERE ts >= ?",
    (since,),
).fetchone()
```

`SourcesPane.reload()` computes `end` but passes only `since_ms`:

```python
# aut_app.py:965-978
start, end = bounds_of(window, model.now_ms())
days = 0 if start is None else max(1, round((end - start) / DAY_MS))
...
self._snaps = snapshots(days, since_ms=start)
```

**Reproduction**

cbut has two rows: `now-3d` (10 tokens) and `now` (90 tokens). Request a window ending at
`now-3d`:

```text
fixed-end snapshot end=now-3d, rows at -3d and now: calls= 2 tokens= 100
```

Only the `-3d` row (1 call / 10 tokens) should count; the `now` row's 90 tokens are counted too.

**Impact**

- A custom historical window's Sources total includes calls made after the window; under the same
  `window`, Dashboard/KPI go through `_where`'s `ts <= end` — the two semantics disagree.
- Directly violates the README promise "Two numbers on one screen count the same calls"
  (`README.md:101`).
- `now` still takes the real current time, so buckets/idle are also computed against "now"
  rather than the custom end.

**Fix direction** (landed in `68b2a9c`: `Source.snapshot` takes an `end_ms` that bounds the
totals, buckets, top rows and the last-event clock; `SourcesPane` and `aut json` pass it through
as `window_end_ms`)
- Add `end_ms` to `snapshot()` / `_read()` and change the SQL to `ts >= ? AND ts <= ?`.
- The bucket `now` and the idle decision should both use `end_ms` (or explicitly separate "data
  window" from "current time").

### P1-4 Sources' idle / last seen is computed only inside the selected window — fixed in `68b2a9c`

**Evidence**

`MAX(ts)` and the totals sit in the same `WHERE ts >= ?` query:

```python
# aut_sources.py:121-126
f" COUNT(DISTINCT session_id), MAX(ts), AVG({self.real_col})"
f" FROM {self.table} WHERE ts >= ?",
```

That `last_ts` then drives the idle decision directly:

```python
# aut_sources.py:158-159
if last_ts is not None and now - int(last_ts) > IDLE_AFTER_MS:
    status = "idle"
```

**Reproduction**

cbut has only one row from 3 days ago; the Sources default window is 1d:

```text
1d snapshot with only 3d-old row: status= ok last= None tokens= 0
```

**Impact**

- Under the default 1d window, `last_ts` can never be older than 7 days, so `idle` never appears.
- "last seen" shows `never`, but the source was used 3 days ago; that is not "never used", it is
  "nothing inside the window".
- It contradicts the README's idle definition (`README.md:151`: "no calls in the last week") and
  `docs/maintenance/tracker-contracts.md:63`.
- Likewise, `tokens=0` makes Sources show 0 although there is real usage outside the window —
  another "0 is a lie".

**Fix direction** (landed in `68b2a9c`: an empty window still reads idle/last-seen from older
history)
- Compute `last_seen` / idle with an unbounded `SELECT MAX(ts)` (one extra query is fine).
- Keep the totals/buckets windowed; when the window has no data but history does, say "no calls in
  this window" rather than `never` / `0`.

### P1-6 The entity average counts NULL durations in the denominator — fixed in `68b2a9c`

**Evidence**


**Impact**

- The Tools/Skills "avg" is systematically understated whenever durations are missing.

### P1-8 Tracker strings enter Rich markup directly, and control characters are not filtered at the entry — fixed in `9570347`

**Evidence**

Several DataTable cells pass DB strings through as plain `str`:

```python
# aut_app.py:481 / 492
"model": row.model,
"provider": row.provider or Text("—", style="dim"),
```

```python
# aut_app.py:578
"name": row.name,
```

```python
# aut_app.py:630 / 1063-1064
"model": row.model or Text("—", style="dim"),
...
fmt_tokens(row.total),
```

Textual 8.2.8's `default_cell_formatter()` calls `Text.from_markup()` on a `str`:

```python
# textual/widgets/_data_table.py (installed version)
if possible_markup:
    text = Text.from_markup(content, end="")
```

**Reproduction**

```text
default_cell_formatter('bad[/red]')
→ MarkupError: closing tag '[/red]' at position 3 doesn't match any open tag
```

At the same time Rich `Text` keeps the raw ESC:

```text
Text('a\x1b]52;c;ZXZpbA==\x07b').plain contains ESC → True
```

The `notify()` subprocess tail (`aut_app.py:1385-1387`) and `_note()`'s `Static.update(text)`
(`aut_app.py:1020-1028`) are likewise parsed as markup by default.

**Impact**

- A `[` in a model/tool/session name (for example `claude[1m]`, `foo[/red]`) can raise
  `MarkupError` inside the renderer and take the whole screen down.
- The Rich layer does not strip ESC; Textual 8.2.8's `Content` strips control codes by default, so
  what is confirmed today is the markup-parse crash, and whether terminal control sequences reach
  the terminal depends on the render path. The code does not filter at the entry, so it should
  still be treated as untrusted input.
- This is not "a style problem" — it is availability and input robustness.

**Fix direction** (landed in `9570347`: every tracker string that becomes a cell goes through
`_cell`, which replaces C0 control characters and builds a `Text`; the Sources note is a `Text`
too and the sync notification sets `markup=False`)
- Wrap every DB string in `Text(value)` (never parsed as markup), or `rich.markup.escape()` first.
- Filter C0 control characters (at least ESC) and use `notify(..., markup=False)` for subprocess
  output.
- Add a fixture with `[` / ESC and assert the TUI neither crashes nor leaks the characters.

### P1-9 `_per_source()` swallows schema drift silently, while Sources can still show ok — fixed in `9570347`

**Evidence**

```python
# aut_model.py:150-158
try:
    out.extend(fn(conn, source, where, params))
except sqlite3.Error:
    # A schema that moved is reported by the Sources tab, not by a
    # traceback in the middle of an aggregate.
    continue
```

But the Sources snapshot queries only a subset of columns:

```python
# aut_sources.py:121-126
f"SELECT SUM({self.expr_total}), SUM({self.cost_expr}), COUNT(*),"
f" COUNT(DISTINCT session_id), MAX(ts), AVG({self.real_col})"
f" FROM {self.table} WHERE ts >= ?",
```

It does not query `provider`, `status`, `duration_ms`, or the entity tables.

**Reproduction**

A cbut DB that keeps `model_responses`' token/ts/project columns but drops the `provider` column:

```text
Sources status= ok tokens= 15
token_rows= []
kpis tokens= 15
```

- Sources and KPI show 15; the Tokens page is silently empty.
- Drop `status` / `duration_ms` / the entity tables instead and Tools/Skills go silently empty
  while Sources stays ok.

**Impact**

- The same source contradicts itself across tabs — "has data" on one, "no data" on another — with
  no error anywhere.
- Directly violates `AGENTS.md:41-42` ("a schema that moved shows `error` on the Sources tab and
  contributes nothing to the merges"): today it "contributes nothing and shows no error".
- `docs/maintenance/tracker-contracts.md:60` and `MAINTENANCE.md:10-11` claim "any renamed column
  makes that source show `error`", which does not hold for columns used only in `aut_model`
  queries.

**Fix direction** (landed in `9570347`: `Source._read` prepares one SELECT naming the columns the
merges need and reports `error` when it fails; `aut_model` records a failed merge query per
(source, query) in `source_errors()` and Sources shows `error` for it)
- Have each adapter declare the columns/tables the merge layer needs; Sources runs the same probe
  on open and marks `error` when something is missing.
- `_per_source()` records each source's error (instead of `continue`) for the caller to aggregate
  into the UI/log.
- At minimum set an observable per-source error state after the `_per_source` catch.

### P1-10 Multi-query reads have no consistent snapshot: one screen can contradict itself during a concurrent sync — fixed in `9570347`

**Evidence**

`Snapshot._read()` issues at least three independent SELECTs:

```python
# aut_sources.py:121-145
# 1) total/cost/calls/sessions/last/avg
# 2) buckets: SELECT date(...), SUM(...) ... GROUP BY d
# 3) top_models / top_projects
```

`DashboardPane.reload()` calls several aggregation functions in turn:

```python
# aut_app.py:700-707
self._kpis = model.kpis(start, end)
self._models = model.model_totals(model.token_rows(start, end))
self._skills = sorted(model.entity_rows("skills", start, end), ...)
self._recent = model.call_rows(start, end, limit=1)
```

Each call opens a fresh read-only connection; no explicit `BEGIN` wraps one source's queries in a
single read transaction.

**Impact**

- While an external tracker is syncing and committing, the Sources total may come from before the
  commit and the trend from after it; the Dashboard's KPIs and model list may likewise come from
  different commits.
- The numbers are not necessarily "wrong", but they contradict each other on one screen, and the
  user cannot tell which moment was the complete snapshot.
- This is a P1 in the concurrent case only; a single-process idle read does not trigger it.

**Fix direction** (landed in `9570347`: `aut_model.read_session()` opens one connection per
source inside one read transaction, every pane's reload and both detail screens run inside it,
and `Snapshot` starts its own read transaction)
- Open one connection per source per reload with an explicit read transaction and run all queries
  through it; cross-source atomicity is still impossible, but at least one source is internally
  consistent.
- Or state on the UI that "each source is read independently and may differ by one sync cycle",
  and avoid stitching instantaneous values from different sources into a strong-consistency
  conclusion.

### P1-11 The `(unknown)` model/entity drill-down cannot find NULL rows; the detail shows 0 — fixed in `68b2a9c`

**Evidence**

`token_rows()` displays a NULL model as `(unknown)`:

```python
# aut_model.py:178
f"SELECT COALESCE(model, '(unknown)'), COALESCE(provider, ''),"
```

But the drill-down matches `IN ('(unknown)')` exactly:

```python
# aut_model.py:384-386
def _model_in(names: tuple[str, ...]) -> tuple[str, tuple[str, ...]]:
    return f"model IN ({','.join('?' for _ in names)})", names
```

`model_stats` / `model_calls` / `model_daily` all go through `_model_in` (`aut_model.py:409`,
`444`, `662`). The entity side is the same: `entity_rows()` groups by
`COALESCE(name_col, '(unknown)')` but `entity_calls()` uses `name_col = ?` (`aut_model.py:476`),
so NULL rows are not found either.

**Reproduction**

cbut with one `model=NULL` row totalling 50 tokens:

```text
unknown row total= 50 stats= (0, 0)
```

**Impact**

- The merged row shows 50 tokens / 1 call; opening it shows 0 tokens / 0 calls, and the user
  concludes the detail page is broken.
- The same class as P1-1 — "merge key and drill-down key disagree" — but triggered by NULL rather
  than by case.

**Fix direction** (landed in `68b2a9c`: the `(unknown)` drill-down)
